Deploying Your Work 🚀

What is deployment?

Deployment means making your project available to others on the internet

Why deploy?

For projects:

  • Share your work publicly
  • Create a portfolio
  • Demonstrate capabilities to employers
  • Get feedback from users
  • Test in real-world conditions

For websites:

  • Personal portfolio/CV
  • Project documentation
  • Blog or research updates
  • Data visualizations
  • Interactive applications

GitHub makes deployment easy and FREE with GitHub Pages! 🎉

GitHub Pages: Free Website Hosting 🌐

What is GitHub Pages?

A free service from GitHub that turns your repository into a website

What can you host?

  • Static websites (HTML, CSS, JavaScript)
  • Personal/project documentation
  • Blogs (using Jekyll, Hugo, etc.)
  • Data visualizations (D3.js, Plotly)
  • Interactive dashboards
  • Your CV/resume

Key features:

  • Free hosting
  • Custom domain support (optional)
  • HTTPS by default
  • Automatic deployment from git
  • No server management needed

Deploying Your First Website 📄

Option 1: Simple HTML site

# In your repository
echo "<h1>Hello World!</h1>" > index.html
git add index.html
git commit -m "Add homepage"
git push origin main

Enable GitHub Pages:

  1. Go to repository Settings
  2. Scroll to “Pages” section
  3. Under “Source”, select branch (usually main)
  4. Select folder (/root or /docs)
  5. Click Save

Your site will be live at: https://username.github.io/repository-name

Wait a minute…

It may take a few minutes for your site to deploy the first time. Be patient!

GitHub Pages with Jekyll 📚

Jekyll is a static site generator built into GitHub Pages

Perfect for:

  • Blogs and documentation
  • Research websites
  • Project pages
  • Academic portfolios

Quick start:

# Create a new repository
# In Settings → Pages, select a theme

# Or use Jekyll locally
gem install bundler jekyll
jekyll new my-site
cd my-site
bundle exec jekyll serve

Then edit these key files:

  • _config.yml - Site configuration
  • index.md - Homepage content
  • _posts/ - Blog posts (dated: YYYY-MM-DD-title.md)
  • about.md - About page

Advanced: Custom Domains 🌍

Want to use your own domain? (e.g., yourname.com instead of username.github.io)

Steps:

  1. Buy a domain (from Namecheap, Google Domains, etc.)

  2. In your repository:

    • Create a file called CNAME containing your domain:
    echo "www.yourname.com" > CNAME
git add CNAME
git commit -m "Add custom domain"
git push

  3. Configure DNS at your domain registrar:

    • Add CNAME record pointing to username.github.io
    • Or use A records to GitHub’s IP addresses

  4. Enable HTTPS in GitHub Pages settings (automatic!)

Full instructions: docs.github.com/pages/custom-domains

Deploying Data Science Projects 📊

Interactive visualizations and dashboards:

Option 1: Static HTML with JavaScript libraries

<!DOCTYPE html>
<html>
<head>
    <script src="https://d3js.org/d3.v7.min.js"></script>
</head>
<body>
    <div id="viz"></div>
    <script src="visualization.js"></script>
</body>
</html>

Option 2: Export from Jupyter/R Markdown

# Jupyter notebook
jupyter nbconvert --to html notebook.ipynb

# R Markdown
Rscript -e "rmarkdown::render('analysis.Rmd')"

Then commit and push the HTML files!

Deploying with Quarto 📝

These slides were made with Quarto! You can deploy Quarto sites too:

Create a Quarto website:

quarto create-project mysite --type website
cd mysite
quarto render

Deploy to GitHub Pages:

# Option 1: Use Quarto's built-in deployment
quarto publish gh-pages

# Option 2: Manual deployment
# Build the site
quarto render

# The output is in _site/
# Push _site contents to gh-pages branch

Your _quarto.yml file:

project:
  type: website
  output-dir: _site

website:
  title: "My Research Website"
  navbar:
    left:
      - href: index.qmd
        text: Home
      - about.qmd

Continuous Deployment with GitHub Actions 🤖

Automate your deployment with GitHub Actions

Example: Deploy on every push to main

Create .github/workflows/deploy.yml:

name: Deploy to GitHub Pages

on:
  push:
    branches: [ main ]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      
      - name: Build site
        run: |
          # Your build commands here
          npm install
          npm run build
      
      - name: Deploy
        uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./dist

This automatically builds and deploys whenever you push!

Deployment Best Practices 📋

Before deploying:

✅ Test locally first ✅ Check all links work ✅ Optimize images (compress large files) ✅ Add analytics if desired (Google Analytics) ✅ Include contact information ✅ Spell check!

Security considerations:

⚠️ Never commit API keys or passwords ⚠️ Use environment variables for secrets ⚠️ Be careful with private data ⚠️ Remember: GitHub Pages sites are PUBLIC

Maintenance:

  • Keep content updated
  • Fix broken links regularly
  • Monitor for issues
  • Update dependencies periodically
