About This Course

Background Information

This course seeks to provide you with a base for your research in economics. In particular, the focus of this course will be on computational methods which are frequently used in economic research. We will be working with scientific programming languages, and discussing themes relevant to conducting research. The goal of this course is that by the end, you will have knowledge of the computation tools necessary to embark on a serious research project in economics, such as a paper or a thesis.

This course is in some sense language-neutral, and I will ask that each of you work with a language that you have never worked with before. In the early portions of the course, information will be provided on a number of languages, and then we will provide instruction in particular in R, Python and Stata. In later parts of the course, we will rotate, considering particular themes in one of these languages, where the focus will be on the substance of the theme, rather than the particular syntax of the language. In this portion of the course, if you have chosen to work in another language, the idea is that you can work on the same these, however in your chosen language. In Tutorials, at one point during the semester, I will request if each one of you could demonstrate to the class how to apply the week’s methods in the language that you have chosen to work with. If, however, you would like to work in another language apart from R, Python or Stata, please let me know, to confirm that this will work.

The only restriction here is that I am requesting that each person start working in a language that they do not have prior experience in. I am doing this for two reasons. The first is that this way we will all start with the same level (none) of language specific knowledge on the particular language we are working in. The second is that in this way, at the end of the semester you will each have knowledge of an entirely new language that may open more doors for you later on. If you have no experience at all programming in the past this is entirely fine. Indeed, I will start this class with the assumption that you have no background knowledge, and so anything that you do know is only a bonus for you (and the class).

The principal resource of this course will be this website which will provide notes, code and code output. A pdf or epub version of these notes can be downloaded at top left-hand corner of the page, though generally presentation is optimised for the website. The site will be updated section-by-section, with each section of the notes going live on the day the class will be given. These resources will then be available on the website for the entire semester. I would encourage you to attend classes in person where ever possible!

Evaluation

The evaluation of this course will consist of the following two elements:

  1. Ongoing assessment (20%): Tutorial presentation (please sign up for your desired slot).
  2. An Empirical Project (80%): Full details provided around week 3 of term. Hand in date is at the end of semester.

Full details on these evaluations will be made available below in line with the dates in the calendar.

Tutorial Presentation

For this evaluation, I will ask you to prepare an example of code for us to work through in the tutorial slot together. The idea of this presentation is that you will show us how to do something that we saw in class, however apply it to the language that you are working with. Thus, the date you present will depend on the language that you decide to work in. The only restriction here is that I will ask you not to present about a specific theme if we have already seen this theme in that language in classes with me. Please refer to the “Language” column in the proposed schedule to ensure that this does not occur.

For this presentation I will ask that you generate an example along the lines of the themes we have seen in class the week before. So, for example, if you wish to present on data management and cleaning and are not working in Stata, you may wish to show us an example of joining some data bases and cleaning particular variables in the language that you are working with. Or if you would like present about data visualisation and graphics and are not working in Python, you may wish to show us how to make some particularly nice graph using real data of interest to you in the language that you are working with.

I would ask that you prepare an example that will take about 10-15 minutes to explain. 10-15 minutes may sound like a long presentation, but when you are explaining your code and the goal of your analysis, it is probably less than you think. You may wish to simply work with code and output in the program that you are working with, or generate some set of slides along side of the code that you will work with in class. I would ask that you show us how the code runs on your computer or on the screen, so that we can look into particular lines of code together. If your presentation generates discussion or extensions and goes for more than 10-15 minutes this is perfectly fine. We will have the entire tutorial block to discuss these examples, and any questions which come up as a result.

Please confirm a date with me and I will include the date for your presentation in the calendar above. Please also feel free to discuss with me the precise themes that we will work with each week if you want to set-up your presentation a few weeks in advance.

Empirical Project

At the end of the semester, please hand in an empirical project. This empirical project is expected to cover the themes discussed in the course, and can be on a topic of your choosing. You should view this empirical project as a mini research project. However what is important in this project is not the results per se but rather the process you follow in bringing everything together.

Some potential ideas of projects could be things such as:

  • Find a paper of interest to you and aim to replicate the question (in a limited way) in another setting

  • Replicate and extend a paper using the data provided by the authors*

  • Examine a number of papers on a similar topic and document how methods and codes vary across papers

  • Find data about some topic of interest to you and run a mini-analysis. In this case, what is important is not empirical design, but rather the process you follow in setting up your project.

  • Write and document some package which can extend the functionality of Python, R or Stata

    * If you choose to replicate a paper, it is not sufficient to simply show that it replicates. The idea is that you should extend the analysis, ideally with further data.

You should not feel like this is the limit of what you can do. If you would like to do alternative things that can be conceived to be an research project, this is great, and please just confirm your intentions with me.

If you wish to check with me about what you propose to do for your empirical project, feel free to ask me or write me at any time! I would encourage you to do so at some point during the term when you start to get an idea of what you would like to do for this project.

Please hand in all the materials you used for your project in a single organised zipped folder (.zip or .7z), or pdf pointing to a github repo or similar. Please hand this in via the submission point on the ELE page of this course no later than 11:59am on Monday 12th of January, 2025. What you hand in will depend a bit on the nature of your project, but at a minimum your materials should consist of:

  • All data and code

  • a README file explaining how to replicate everything you have done

  • A compiled pdf containing sections including: Introduction, Data, Methods, Results, and Conclusion. This pdf should not exceed 15 pages. If you wish to include appendix results this is fine, and will not count towards the 15 pages.

The evaluation of the project will consider the elements below. The “proportion” refers to the approximate importance that these elements will be given in the final mark. The final mark will consist of an overall grade along with written comments from me, but will not provide an itemised break down, and as such the elements below are simply to help you ensure that your project touches on all relevant components. Marking will follow the typical system used in the MRes where 50 or above is a pass, 70 or above signifies excellent work (ie a level of first class honours), and 80 signifies something truly outstanding.

General Comment

There is no single “correct” way for this to be done, and it depends on exactly what your project is like. If, however, you are applying the tools of the class to some particular research question of interest (such as the fourth bullet point of the list at the top of this description), I would suggest that you should hand in a pdf structured as follows:

  1. Introduction - Around 1-3 pages, noting the context you are looking at, explain what you do, citing some key literature and the motivation (somewhat similar to a short version of the introduction of a standard economic paper)

  2. Data - Around 2-5 pages, explaining fully the data you use, any cleaning done, any other information useful for readers, and providing full summary statistics and relevant descriptives

  3. Methods - Around 1-2 page, explain simply what you will do, laying out any estimating equations. Here you could also include information related to weighting of models (if relevant), or other key methodological points

  4. Results - Around 2-6 pages, providing any results you produce which may be tables, graphs, and so forth. Explain to me what you find, and the implications of this, noting any key limitations

  5. Conclusion - Around 1 page, simply summarising what you have found, any key take-aways, key limitations, and future work that may be motivated by this project

  6. Bibliography

Please note, the above description may not correspond exactly to what you are doing, and so should be viewed as simply one particular way that this could be addressed, rather than a prescriptive list which must be followed. Please talk to me if you would like to discuss what you are doing, or get any interim feedback!
