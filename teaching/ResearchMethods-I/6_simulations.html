Simulations as Part of Research Workflow

Introduction

In this class we will examine a number of cases in which we wish to use either simulation or processes based on randomisation within our research. Simulation in particular can be a useful way to examine the performance of a particular estimator. Generally, when we are working with real data and some estimator of interest, we can not separate out the process of testing our estimator from any identifying assumptions we may have. Given that we do not know the real population value that we wish to recover, we cannot test our estimator in a controlled way. Simulation, and Monte Carlo methods, allow us to examine how a particular estimator performs under some controlled circumstance where we define the data generating process (DGP), and hence where we know the value that the estimator should return if we repeat simulation many times.

In general, if we are using standard estimators in commercial or highly used software in our research we probably do not need to worry that the underlying estimation routines may be incorrect. However, if we are writing our own estimators, this process of simulating to see how an estimator peforms when the DGP is known will be a fundamental part of testing our code.

In this class we will begin by considering a simple example of such a process which seeks to illustrate the idea of such a test. We will then move on to consider a number of other processes that we may encounter in which randomisation is used in our research: specifically bootstrap and randomisation inference procedures.

Monte Carlo Simulations to Examine Estimators

To see a simple example of Monte Carlo simulations, we will use the following data generating process:

\(y_i = \beta_0 + \beta_1 x_i + \varepsilon_i\)

where \(\beta_0=1\), \(\beta_1=2\), and both \(x_i\) and \(\varepsilon_i\) are distributed \(\mathcal{N}(0,1)\). Having conducted this simulation, we will estimate a regression model to estimate \(\widehat\beta_1\). We will then see if our estimator \(\widehat\beta_1\) recovers the true population parameter \(\beta_1\). This is not as elaborate as a procedure when we may wish to incorporate Monte Carlo simulations in our own research, mainly because the estimator itself is quite simple (OLS), and we already know the properties. But it is worth confirming to ourselves that we understand the mechanics of this so that we can extend to more complex cases if desired.

Below we start writing code for a single simulation in Python. We will use numpy for pseudo-random number generation, and scikit-learn for regression estimation. We can see in this particular example that we estimate a value for \(\widehat\beta_1\) of 2.09: quite close to the true “population” parameter.

import numpy as np
import pandas as pd
from sklearn.linear_model import LinearRegression

# Generate independent variable (X) and dependent variable (Y)
np.random.seed(1213)
N = 1000
x = np.random.rand(N, 1)  # 1000 observations of a single independent variable
y = 1 + 2*x + np.random.randn(N, 1)  # Linear relationship with some noise


data = pd.DataFrame({'x': x[:, 0], 'y': y[:, 0]})
#Could also do:
#data = pd.DataFrame({'x': x.flatten(), 'y': y.flatten()})

# Create a LinearRegression model
model = LinearRegression()

# Fit the model to the data
model.fit(data[['x']], data[['y']])

# Coefficients
beta1hat = model.coef_[0][0]
beta0hat = model.intercept_[0]

print(f"beta 1 (Coefficient): {beta1hat}")
print(f"Intercept: {beta0hat}")

Intercept: 0.9734410595829046

Now we can consider the Monte Carlo simulations themselves. Here, instead of estimating a single value for \(\widehat\beta_1\) we can ask how our estimator performs across repeated sampling. Below we will repeat the process from above 500 times, in each iteration (with each different realisation of data from the underlying DGP), saving the resulting parameter. Based on this we can see what the distribution of estimated paramters \(\widehat\beta_1\) looks like:

#Now do this 500 times to see distribution of beta hat
# Create an empty list to store slope coefficients
beta1hats = []

# Perform the simulations and regressions 500 times
for _ in range(500):
    # Generate synthetic data
    x = np.random.rand(N, 1)
    y = 1 + 2 *x + np.random.randn(N, 1)

    # Create a DataFrame
    data = pd.DataFrame({'x': x[:, 0], 'y': y[:, 0]})

    # Create a LinearRegression model and fit it to the data
    model = LinearRegression()
    model.fit(data[['x']], data[['y']])

    # Extract the slope coefficient and store it
    beta1hats.append(model.coef_[0][0])

# Calculate mean estimate of beta 1 hat
print('Mean coefficient estimate is: ' + str(np.mean(beta1hats)))

# Create a histogram of the slope coefficients
plt.figure(figsize=(8, 6))
plt.hist(beta1hats, bins=30, edgecolor='black', label='Estimates')
plt.axvline(2, color='red', linestyle='dashed', label=r'$\beta_1$')
plt.xlabel(r'$\widehat\beta_1$')
plt.ylabel('Frequency')
plt.legend()
plt.grid(True)
plt.show()

Alternative Methods Based on Pseudo-Random Draws

In practice, Monte Carlo simulation is just one of a number of cases where we may use pseudo-randomness in our research. Here we will consider a number of other cases. This includes the use of bootstrapping to generate standard errors, and the use of permutation inference. We turn to these in turn.

Bootstrap Inference

The idea of bootstraping is that we can get at the variation of a parameter through resampling. For example, if we do not wish to estimate an analytic standard error, we can estimate the standard error of an estimate by resampling with replacement many times from our original data, in each case estimating the parameter of interest based on the “new” (resampled) data. This procedure was initially proposed by Bradly Efron in his doctoral thesis, and formal deatils can be found in, among many other places, Efron and Tibshirani (1993). The below figure describes bootstrapping in a schematic way.

To explore bootstrapping, we will return to the data we have used multiple times throughout this course, and estimate a simple regression of salary on education and experience. Below we estimate the regressino based on the true data, using statsmodels this time, to easily access the parameter standard error for reference.

import wooldridge

mroz = wooldridge.data('mroz')

salaryData = mroz.loc[mroz['lwage'].notna()].copy()   
salaryData['exper2'] = salaryData['exper']**2

X = salaryData[['educ', 'exper', 'exper2']]
X = sm.add_constant(X) 

model = sm.OLS(salaryData['lwage'], X).fit()
print(model.summary())

print(model.params['educ'])

The above parameters are the regression estimate, and the analytic standard error. However, if we would like to calculate the bootstrap version of this standard error, we can resample many times from the original data, in each case estimating a new version of \(\widehat\beta_1\), which we will call \(\widehat\beta_1^{*}\). The bootstrap standard error then is simply defined as \(\text{std.\ dev}(\widehat\beta_1^{*})\). Below we do this using 1,000 bootstrap replicates.

mroz = wooldridge.data('mroz')

originalData = (
    mroz.loc[mroz['lwage'].notna(), ['lwage','exper','educ']]
      .copy()
      .assign(exper2=lambda d: d['exper']**2)
)

B = 1000
Bstar = []

for _ in range(B):
    resample = originalData.sample(frac=1, replace=True)
    X = sm.add_constant(resample[['educ','exper','exper2']])
    fit = sm.OLS(resample['lwage'], X).fit()
    Bstar.append(fit.params['educ'])

plt.hist(Bstar)
np.std(Bstar)
np.float64(0.012756853593999078)

We can see here that this process of bootstrapping results in a distribution of \(\widehat\beta_1^{*}\) (presented as a histogram), and corresponding standard error estimate of 0.0127. This is an aymptotically consistent standard error, and this process can be used in a remarkable array of models provided that resampling with replacement is conducted to generate many replicates of the underlying estimate of interest.

Randomization Inference

Randomization inference, originally laid out in Fisher (1935) provides quite a clean way of thinking about uncertainty. What’s more it is valid in small samples, providing a \(p\)-value without the need for any distributional assumptions or large sample asymptotics. Fisher’s method allows for the testing of sharp null hypotheses. Here we will illustrate the idea of randomization inference assuming that we have data where each individual is exposed to some treatment or not, and we will use \(W_i=1\) to imply treatment exposure, and \(W_i=0\) if an individual is not exposed to treatment. A sharp null hypothesis refers to the test where the null imposes a precise treatment effect for every individual. This is commonly that the impact of treatment is precisely zero for each individual. The alternative hypothesis in this case is that for at least one observation, the effect of treatment is not zero.

We will use the notation \(Y_{i1}\) to refer to the outcome \(Y\) of a given individual had they been exposed to treatment. We will similarly use the notation \(Y_{i0}\) to refer to the outcome of an individual had they not been exposed to treatment. We will refer to these values as potential outcomes. In practice, we will only observe one of these outcomes: either \(Y=Y_{i1}\) if an individual is exposed to treatment, of \(Y=Y_{i0}\) if they are not exposed to treatment. The logic of randomization inference is that under the sharp null hypothesis, all the values of unobserved potential outcomes are known. If, for example, \(Y_{i1}=Y_{i0}\), then the observed value can be used to infer the unobserved value under the null, and as a result any alternative sample be generated. Given this, we can generate a distribution of test statistics which is true under the null hypothesis by permuting the sample assignment mechanism, and re-calculating the test statistic of interest (for example, the difference in means) in the resulting alternative sample. Here, permutation refers to taking the treatment assignment, and randomly shuffling it around such that units are assigned a potentially different treatment status, and then re-calculating the same test statistic based on the original realisation of \(Y_i\), but the new assignment of \(W_i\). If the treatment does indeed have a large effect, we would expect that the true treatment effect should be substantially larger than versions which are recalculated based on arbitary assignments of \(W_i\). However, if treatment does not have a substantial effect, we may expect that the true treatment effect is similar to versions calculated off alternative permutations of treatment.

This can be formalized via the calculation of a \(p\)-value. Consider now a treatment effect calculated based on the true sample, denoted \(\tau(W^{obs},Y^{obs})\), where each individual’s outcome \(Y_i\) is associated with their true treatment assignment \(W_i\). Also, consider potentially many treatment effects calculated based off alternative permutations of treatment assignments, denoted \(\tau(W^{perm},Y^{obs})\), where now the true outcome \(Y_i\) of each individiual is associated with randomly re-permuted realisations of \(W_i\). In this case, a \(p\)-value can be calculated as the proportion of times which permuted treatment effects exceed the true treatment effect, or: \[\begin{equation} \text{Pr}\left(\left|\tau(W^{perm},Y^{obs})\right|\geq \left|\tau(W^{obs},Y^{obs})\right|\right). \end{equation}\] This \(p\)-value is at times referred to as Fisher’s exact \(p\)-value. In this particular example, the \(p\)-value is calculated based on the underlying treatment effect, and below in code we will consider an example where this treatment effect is a difference of means: \(\widehat\tau =E[Y_i|W_i=1]-E[Y_i|W_i=0]\).

Exact p-values

Here we will consider an example based on a small data set. Consider the case of 6 units, with 3 observations randomly assigned treatment. Imagine that the observed outcomes were then, in the treatment group: \((34,27,29)\), and in the control group: \((14,18,24)\). A simple comparison of means estimator suggests that the treatment effect is 11.33. To calculate a p-value, we can permute all the possible combinations, and ask what proportion of these are greater than or equal to this treatment effect. If we consider random orderings of 6 units, this suggests that there are \(6!\) possible combinations, but in reality, as we are randomly choosing 3 units from these 6 to assign a permuted treatment status, the actual value of different combinations is \(6\choose 3\) \(=\frac{6!}{3!*(6-3)!}=20\). We document each of these possible permutations, as well as their permuted treatment effect in the Table below. In this case, we can see that only 1 of the 20 different permutations is greater than or equal to 11.33 he original treatment status). Suggesting an exact p-value of \(1/20=0.05\).

We will set this up in Python. First, we will load the required libraries:

#Load required libraries
import pandas as pd
import numpy as np
from itertools import permutations
import matplotlib.pyplot as plt
import seaborn as sns

We will now enter data as a Pandas data frame, and subsequently calculate the difference in means estimator in a number of lines. You will note that in calculating the differnce in means estimator, we are first sub-setting using logical indexing (for example: data[data['W']==1], which means “choose all rows of data for which \(W=1\)”). Then, we calculate the means in each group using the Pandas mean() operator.

#Enter data as Pandas data frame
data = {'Y': [34, 27, 29, 14, 18, 24],
        'W': [1, 1, 1, 0, 0, 0]}
data = pd.DataFrame(data)


#Calculate Difference in means estimator  
Y1 = data[data['W']==1]['Y']
Y0 = data[data['W']==0]['Y']
tau = Y1.mean() - Y0.mean()
#Generate permutations of W
perm=permutations([1,1,1,0,0,0])
#Wperm=perm
Wperm = set(perm)

Taus = []
for p in Wperm:
    dataP = pd.DataFrame({'Y': [34, 27, 29, 14, 18, 24], 'W': p})
    tauP = dataP[dataP['W']==1]['Y'].mean()-dataP[dataP['W']==0]['Y'].mean()
    Taus.append(tauP)


p_2side = sum(np.absolute(Taus)>=tau)/len(Taus)
p_1side = sum(Taus>=tau)/len(Taus)

print("The two-sided p-value is: " + str(p_2side))
The two-sided p-value is: 0.1

plt.show()

Randomization inference with a larger dataset

An element which simplifies randomization inference is that permutation simply respects the original treatment assignment in the data. Thus, if in some sample of \(N\) observations \(N_T\) receive treatment and \(N_C\) receive control, each permutation should randomly re-assign a new \(N_T\) of these observations to treatment, and \(N_C\) to control. In each permutation, the same \(N\) observations exist, and no units are repeated – treatment assignment \(W_i\) is just shuffled around. Given that this is just simply choosing treatment at random without replacement, this implies that there are \(N\choose N_T\) possible ways which treatment could be applied. For the sake of completion, the notation \(N\choose K\) refers to “\(N\) choose \(K\)”, or the number of ways which \(K\) units can be chosen from \(N\) units. The explicit formula for calculating \(N\choose K\) is \(\frac{N!}{K!\times(N-K)!}\), where \(J!\) refers to \(J\times(J-1)\times\cdots\times 1\). Where there are quite a small number of units, the \(p\)-value above can be calculated exactly, which is to say that each possible re-assignment be considered. For example, in the experiment with 6 observations, 3 of which are assigned to treatment, the number of different combinations is \(6\choose 3\) \(=\frac{6!}{3!\times(6-3)!}=20\). In settings such as these, we can consider the value of \(\tau(W^{perm},Y^{obs})\) under each possible permutation, and consider how extreme \(\tau(W^{obs},Y^{obs})\) is compared to these 20 realisations. However, where we have a larger number of observations, we cannot calculate an exact \(p\)-value. Even with quite moderate number of observations, the total number of possible combinations grows very quickly. For example, while 10 units with 5 randomly assigned treatments gives a reasonably manageable \(10\choose 5\) \(=252\) possible combinations, this grows quickly, with 20 units and 10 treatments resulting in \(20\choose 10\) \(=184,756\) possible combinations, and 30 units and 15 treatments a massive \(30\choose 15\)=155,117,520 possible combinations. For this reason, we generally calculate a relatively large number of permutations at random. With a larger dataset, this procedure can be conducted as follows:

  1. Preserve the original treatment assignment.
  2. Generate placebo treatment statuses according to the original assignment method.
  3. Estimate the original regression equation with an additional term for the placebo treatment.
  4. Repeat #1–3.
  5. The randomization inference p-value is the proportion of times the placebo treatment effect was larger than the estimated treatment effect.

In the interests of space we will not explore this here, but note that this is something which can be conducted even in very large datasets.
