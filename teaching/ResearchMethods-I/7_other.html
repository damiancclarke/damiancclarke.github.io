Some Details on Webscraping

Introductory Details

Throughout this course we have generally been assuming that our data will be available as a csv file, or some other clean format. In practice, data is often not so conveniently available. At times, data may be housed on the internet in a diffuse form, and we need to do some work to generate our data. In processes such as this, webscraping may be a very useful tool for us. A nice discussion of webscraping (and web based data more generally) in economics is available in the paper by Edelman (2012).

Webscraping is essentially, the process of harvesting data that is directly stored on the web in an irregular or highly disperse format. When undertaking economic or econometric analysis, we of course want very regular data, formatted into lines and columns. The process of webscraping to turn data on the web into data which can be used in analysis generally requires two main steps:

  1. Looping through nested urls to get to (many) source html pages
  2. Taking html (or some other output) and formatting into a useful structure

This second step can download all manner of things. For example, we may wish to download data stored as plain text, and formatted as html, json, xml, and so forth, or other files, such pdfs, xls, images, and so forth. Once we have downloaded this information, we can then process them as required. There are many ways that webscraping can be done. Later in this class we will see some examples in Python, which is quite flexible and easy to use for webscraping.

We will generally come to webscraping when we have found that the data we need is available on some website, but there is no simple way to download it in a single click. We may need to download many different pages or documents on the web, or fill in a form many many times. If this is not practice given the sheer volume of information, we may wish to webscrape. However, before we embark on webscraping, there are a few considerations that we should keep in mind. This includes:

1. Are there legal limits? Some websites do not allow webscraping. This may be because they consider their information proprietry, or because they wish to avoid robot traffic slowing down servers. The law here is complex and depends upon jurisdiction, but there are certainly precedents suggesting it can be troubling, for example LinkedIn Corporation vs. Does, 1 through 100 inclusive. Where possible, seek permission prior to web-scraping and read any Terms of Service which may be available. A more direct way to see what a site maintainer expects is to read the robots.txt file which is available on most pages at the top level (for example, see https://xkcd.com/robots.txt). This robots.txt file should give us an idea of what webcrawlers are allowed to access, and what they are not, and we should respect this when writing webscraping code.

2. Is the target standardized enough? As we will see below, webscraping requires us to interact with the source code (html or xml) of websites. Webscraping will be considerably harder if we are trying to get data off of many disperse websites rather than many pages within a single site. It will also be more challenging of source/format of data within a site changes over time, for example working with a repository where in early years, pdfs are scanned, and in later years machine-readable. Independent of this, some websites are stored on very unstable servers. If the connection to a site is hard to maintain, it will mean webscraping will be a fair bit harder!

3. Are there technical limits? Many websites have safeguards against excessive crawling or scraping (for example “Completely Automated Public Turing test to tell Computers and Humans Apart”). Sometimes these will be quite simple things like limiting rate of requests or temporarily blocking IPs. These can often be worked around by slowing the rate of webscraping. In the more complicated case where IPs are blocked completely, you could consider looping over different IPs, eg using proxies or TOR. However, this is not trivial, and if a site is seeking to block access, we should probably take this as a sign that we should seek alternative data, or alternative ways to access data.

Before we turn to consider some real examples, it is also worth noting that we may be able to avoid the process of webscraping alltogether. Some websites have simpler ways to gain access to data. The site Ideas/RePEc is a great example of this; see https://ideas.repec.org/getdata.html. Other sites may also have APIs (perhaps at a cost) to simplify tasks, or, alternatively, upon request, owners of sites may be happy to provide you data. In general, if you need to write scripts to scrape data off the web you should be aware of the fact that many calls to a website’s server may be problematic for that site, and seek to be judicious with the way you interact with websites.

A Simple Example with Python

To see the general idea of this, we will go through a relatively simple (and contrived) example. For this process, there are a number of tools we will use:

  • Ideally, a web browser that lets us look at source code (pretty much any of them)
  • Functions to get source code from the web (Python’s urllib library)
  • Regular Expressions (Python’s re)
  • If this is a big job, we should think about error capture (via the try command)

To see this, let’s look at a particular code that iterates through a site, getting a piece of information from each webpage. We will discuss the idea of this at more length in class…

#  Scrape_xkcd 0.01              damiancclarke             yyyy-mm-dd:2023-12-03
#---|----1----|----2----|----3----|----4----|----5----|----6----|----7----|----8
#
# Syntax is: python Scrape_xkcd.py
#
# This file scrapes xkcd to find the total number of comics, and the prints out
# each comic's name.  It is not meant to be remarkably useful, rather it simply
# demonstrates the use of Python's urllib library, and some basic regular expr-
# ession searches.

#-------------------------------------------------------------------------------
# (1) Import required packages, set-up names used in urls
#-------------------------------------------------------------------------------
from urllib import request, error
import re

target = 'http://www.xkcd.com'


#-------------------------------------------------------------------------------
# (2) Scrape target url and find the last comic number
#-------------------------------------------------------------------------------
response = request.urlopen(target)

for line in response:
    line = line.decode('utf-8')
    #print(line)
    if 'Permanent' in line:
       print(line)
       lastComic = re.findall(r'\d+', line)[0]

#-------------------------------------------------------------------------------
# (3) Loop through all comics, finding each comic's title or capturing errors
#-------------------------------------------------------------------------------
output = open('xkcd_names.txt', 'w')
output.write('Comic, Number, Title \n')

#Currently, we iterate through 10 comics: should start from 1
for comic in range(3160,int(lastComic)):
    url = target + '/' + str(comic)
    try:
        response = request.urlopen(url)
        for line in response:
            line = line.decode('utf-8')
            if 'ctitle' in line:
                print(line[17:-7])
                output.write('xkcd,' + str(comic) + ',' + line[17:-7] + '\n')
                        
    except error.URLError as e:
        print(f"URLError: {e}")
    except error.HTTPError as e:
        print(f"HTTPError: {e}")
    except:
        print("Other error")

output.close()

An Aside on Regular Expressions

Regular Expressions (or regex) are a standardised way to search within text to match patterns. Above we have used these for a quite simple task (finding a string of numbers within a text). Most languages with string capabilities have their own regex libraries. While precise syntax varies by language, there is a standard set of tools. These can often be quite simple, such as the example above, however can become very complex (for example, the famous example of a complete email validation regex. It is worth looking at syntax for language you are using, and working through examples (see here for Python syntax/examples).

Other Tools

BeautifulSoup

There are a number of other tools which may be useful to do webscraping. One tool, which can easily be integrated into the work above is Beautiful Soup. Beautiful Soup is a library which seeks to systematise the html scraped off a webpage, and simplify the process of parsing data from a page. For example, if we wish to get the title of each comic, which we did using a string search in the code above, we could also use Beautiful Soup, and ask it to return the title string directly (see below). This can be installed directly from pip with pip install beautifulsoup4. Further details related to its functionality can be found on the Beautiful Soup homepage, or documentation.

#  Scrape_xkcd 0.01              damiancclarke             yyyy-mm-dd:2025-12-05
#---|----1----|----2----|----3----|----4----|----5----|----6----|----7----|----8
#
# Syntax is: python Scrape_xkcd.py
#
# This file scrapes xkcd to find the total number of comics, and the prints out
# each comic's name.  It is not meant to be remarkably useful, rather it simply
# demonstrates the use of Python's urllib library, and some basic regular expr-
# ession searches.

#-------------------------------------------------------------------------------
# (1) Import required packages, set-up names used in urls
#-------------------------------------------------------------------------------
from urllib import request, error
import re
from bs4 import BeautifulSoup


#-------------------------------------------------------------------------------
# (2) Loop through comics, finding each comic's title
#-------------------------------------------------------------------------------
target = 'http://www.xkcd.com'
output = open('xkcd_names_2.txt', 'w')
output.write('Comic, Number, Title \n')

for comic in range(1,10):
    url = target + '/' + str(comic)
    response = BeautifulSoup(request.urlopen(url),'html.parser')
    title = response.title.string
    print(title)
    
    output.write('xkcd,' + str(comic) + ',' + title[6:] + '\n')

output.close()

Selenium

The above scripts have assumed that all the data which we need can be scraped directly from the source code of a page. However, in some cases this is not possible, but instead either some form needs to be completed which will provide data, or some series of boxes need to be ticked resulting in some output that can only then be processed. In cases where we wish to navigate through some web browser in an automated way, Selenium is a very useful tool. We will discuss some examples of this in class. The documentation for Selenium can be found here (including some examples) should you require more advanced tools of this type for your work.
